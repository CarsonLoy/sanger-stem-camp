# Instructions for Codex and Other Contributors

## Read first

Before editing the website, read:

- `PROJECT-BRIEF.md`
- `docs/CONTENT-INVENTORY.md`
- `docs/RESOURCES-AND-BUDGET.md`
- relevant files under `docs/days/`

## Non-negotiable rules

1. Do not invent facts.
2. Preserve all `TODO:` markers until a human supplies the missing information.
3. Keep the main user journey chronological and checklist-driven.
4. Do not hide required steps inside narrative prose.
5. Keep “What we did” separate from “Recommended approach.”
6. Classify supplies by acquisition type:
   - buy
   - check inventory
   - specialized equipment
   - source locally/collect
   - optional
7. Do not imply that nine 3D printers, 32 computers, or 12 Makey Makeys are required for every version of the camp.
8. Do not create a backend, authentication system, or database.
9. Maintain accessible contrast, keyboard navigation, alt-text support, and print styles.
10. Run the production build before reporting completion.

## Design direction

The site should feel like a friendly engineering field guide:

- practical
- clean
- energetic but not childish
- easy to scan on a phone
- clear enough to use during setup or instruction

Prefer checkboxes, numbered steps, compact tables, warnings, and troubleshooting callouts over decorative marketing sections.

## Content editing

Do not rewrite firsthand details in a way that changes their meaning. Correct spelling and grammar while preserving the actual procedure.

When a price is displayed, include the date captured and note that prices can change.
